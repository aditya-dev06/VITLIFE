# VIT Life — Security Fixes + Ask AI Chat Full Upgrade

## Context
- App: React 19 + Vite frontend / Express monolith (`server/server.js`, 8,169 lines) / MongoDB + Redis / Gemini AI / Pusher.
- Audit found: Gemini API key leaked in URL query strings, upstream error disclosure, a fake unauthenticated `/api/chat/meta-ai`, no rate limit on `/api/chat/report`, extension-only upload validation. The Ask AI chat is single-turn (no memory), non-streaming, loses all history on tab switch, and has no copy/stop/regenerate/mode UI.

## Part A — Security fixes (high + medium)

**A1. Remove API key from URLs (high)** — `server/server.js:5288-5294`, `5360-5379`, `2275-2313`
- Delete `?key=${apiKey}` from all Gemini URLs; authenticate exclusively via the `x-goog-api-key` request header (add it to the model-discovery fallback calls that currently lack it).

**A2. Stop leaking upstream errors (high)** — `server/server.js:5388`, `4964`
- Return a generic message to clients; log full details server-side only.

**A3. `/api/chat/report` hardening (medium)** — `server/server.js:7632`
- Add a dedicated rate limiter (~10 reports / 15 min / IP) so anonymous report spam can't flood moderation.

**A4. Magic-byte upload validation (medium)** — new helper + apply at `server/server.js:7308` (chat upload) and `:4981` (paper upload)
- Sniff file signatures (JPEG/PNG/GIF/WebP/PDF/DOC/DOCX) from `req.file.buffer`; reject mismatches with 400.

## Part B — Ask AI full upgrade

**B1. Server: rewrite `/api/papers/ask-pyq` → multi-turn + SSE streaming**
- Accept `messages` history (capped ~12 turns), build proper Gemini `contents` turns + `systemInstruction` (paper context stays in system prompt; user query becomes a user turn — also reduces prompt-injection surface).
- Switch to `streamGenerateContent?alt=sse`; proxy deltas to the client as `text/event-stream` (`data: {"delta": "..."}`, final `data: {"done": true, answer, ...}`).
- Add per-attempt timeouts (`AbortSignal.timeout`), trim the fallback chain to 2–3 models, keep header-only auth. Non-stream fallback via `stream:false` flag for safety.

**B2. Server: AI session persistence (MongoDB)**
- New `ai_chat_sessions` collection keyed by user + paper. Endpoints under `authenticate`: `GET /api/ai/sessions/:paperId` (latest session), `POST /api/ai/sessions` (upsert messages), `DELETE /api/ai/sessions/:paperId` (clear). Cap stored messages at 100.

**B3. Frontend: AI tutor overhaul in `CommunityPage.jsx` (+ new `src/hooks/useAiTutorSession.js`)**
- Lift session state to a hook at CommunityPage top level so sub-tab switches don't unmount it; restore from `localStorage` instantly on app-level remount, then sync from server when authed.
- Streaming client: parse SSE via ReadableStream, render tokens as they arrive with a typing cursor.
- UX actions: **Stop** (AbortController), **Regenerate** last answer, **Copy** per message, **New chat** (clears local + server session), mode chips (Explain / Quiz / Solutions / Topics — server already supports these), suggested starter prompts on empty state.
- Smart auto-scroll (only when user is near bottom), friendly 429/error states with retry.

**B4. Meta AI drawer → real Gemini**
- Server `/api/chat/meta-ai` rewrite: `optionalAuthenticate` + `aiAssistantLimiter`, real Gemini call with the quoted message as context and multi-turn follow-up history; request structured JSON (summary / keyInsights / aiResponse / quickReplies) via `responseMimeType: application/json`. HTML-decode sanitized text before sending to Gemini.
- `MetaAIDrawer.jsx`: send auth header, render responses as markdown (ReactMarkdown), pass prior drawer turns for context.

## Part C — Verification
- `npm run lint` and `npm run build` must pass.
- Run backend + frontend dev servers; verify: streaming works, multi-turn remembers context, stop/copy/regenerate function, session survives sub-tab switches and page reload, Meta drawer returns real AI text, renamed-file upload (`.exe` → `.jpg`) is rejected, report endpoint rate-limits.
- No changes to Capacitor/TWA config; `.env` keys untouched.
